# TacviewTCPlink 使用手册

## 1. 模块用途

该模块把任意数据源的对象状态实时发送给 Tacview，并可同时保存为 `.acmi` 文件。
它不依赖飞行器类或机动模型。数据可以来自仿真程序、UDP、串口、CSV 回放或其他系统。

使用者通常只需包含 `tacview/Tacview.h`，并接触一个类：`tacview::Tacview`。

## 2. 最小使用流程

```cpp
#include "tacview/Tacview.h"

tacview::Tacview output;

if (!output.start()) {
    std::cerr << output.lastError() << '\n';
    return;
}

output.addObject({1, "F-16C", "Air+FixedWing", "Blue"});

tacview::ObjectState state;
state.id = 1;
state.time = simulationTime;
state.longitude = longitudeDeg;
state.latitude = latitudeDeg;
state.altitude = altitudeM;
state.roll = rollDeg;
state.pitch = pitchDeg;
state.yaw = yawDeg;
output.update(state);

output.stop();
```

完整示例位于 `examples/TacviewExample.cpp`。

## 3. 固定单位

| 字段 | 单位 | 有效范围 |
|---|---|---|
| `time` | 秒 | 大于等于 0 |
| `longitude` | 度 | -180 到 180 |
| `latitude` | 度 | -90 到 90 |
| `altitude` | 米 | 有限数 |
| `roll/pitch/yaw` | 度 | 有限数 |

对象 ID 必须大于 0，因为 ACMI 保留 ID 0 表示全局属性。

## 4. 常用配置

```cpp
tacview::Options options;
options.port = 42674;
options.serverName = "My Simulator";
options.dataSource = "My Data Source";
options.recordingFile = "flight.acmi"; // 留空则不保存文件

tacview::Tacview output(options);
```

模块启动后在指定端口等待 Tacview。Tacview 晚于仿真连接也没有问题：新客户端会自动收到 ACMI 文件头和所有对象的最新状态。

## 5. 多对象和对象删除

每个对象使用唯一 ID：

```cpp
output.addObject({1, "Leader",   "Air+FixedWing", "Blue"});
output.addObject({2, "Wingman",  "Air+FixedWing", "Blue"});
output.addObject({3, "Opponent", "Air+FixedWing", "Red"});

output.update(leaderState);
output.update(wingmanState);
output.update(opponentState);

output.removeObject(3, simulationTime);
```

必须先 `addObject()`，再为该 ID 调用 `update()`。

## 6. 数据源适配

模块不要求数据源继承任何类。只需在取得一帧数据后填充 `ObjectState`：

```cpp
void sendToTacview(const ExternalData& source, tacview::Tacview& output) {
    tacview::ObjectState state;
    state.id = source.objectId;
    state.time = source.timestamp;
    state.longitude = source.lon;
    state.latitude = source.lat;
    state.altitude = source.alt;
    state.roll = source.roll;
    state.pitch = source.pitch;
    state.yaw = source.heading;
    output.update(state);
}
```

这层转换是数据源唯一需要编写的适配代码。

## 7. 错误处理

`start()`、`addObject()`、`update()` 和 `removeObject()` 返回 `bool`。失败后使用：

```cpp
std::cerr << output.lastError() << '\n';
```

模块会拒绝重复 ID、未注册对象、NaN、无穷值及非法经纬度，不会把无效数据发送给 Tacview。

发送队列有固定容量，默认可缓存 4096 条消息。如果生产速度长期超过网络发送速度，模块会丢弃最旧消息并始终保留对象最新状态；可通过 `queueCapacity` 调整容量。

## 8. 内部框架

```text
任意数据源
    │ ObjectState
    ▼
tacview::Tacview
    ├── 输入校验与对象注册表
    ├── AcmiEncoder（ACMI 2.2 文本）
    ├── 有界异步发送队列
    ├── Winsock TCP 服务与客户端快照
    └── 可选 ACMI 文件记录
```

`AcmiEncoder` 不接触网络；网络线程不依赖飞行器或机动模型。公开头文件也不包含项目中的飞行器类型。

## 9. 发布集成

推荐直接使用本目录的 CMake。手工加入 Visual Studio 工程时需要以下文件：

- `include/tacview/Tacview.h`
- `include/tacview/AcmiEncoder.h`
- `src/Tacview.cpp`
- `src/AcmiEncoder.cpp`

工程需要链接 Windows 系统库 `Ws2_32.lib`。源码已包含 MSVC 的自动链接指令，通常无需手工配置。

要求 C++14 或更高版本；推荐 C++17。模块没有 SimTools、Eigen 或机动模型依赖。

也可以只构建独立静态库：

```powershell
cmake -S AircraftClass/TacviewTCPlink -B build/tacview
cmake --build build/tacview --config Release
```

`CMakeLists.txt` 默认只编译 Tacview 模块，不会编译当前项目的机动模型。

运行内置的编码及公共 API 测试：

```powershell
ctest --test-dir build/tacview -C Release --output-on-failure
```

生成可复制给其他项目的发布目录：

```powershell
cmake --install build/tacview --config Release --prefix package/TacviewTCPlink
```

安装结果包含 `include`、`lib` 和 `docs` 三个目录。

Debug 配置生成 `TacviewTCPlink_d.lib`，Release 配置生成 `TacviewTCPlink.lib`。链接时应选择与应用程序运行库配置一致的版本。

## 10. VS2019 集成方法一：直接加入源码

这是最简单、最容易排查问题的集成方式，不要求使用 CMake，也不需要预先生成静态库。

### 10.1 创建项目

在 Visual Studio 2019 中新建“控制台应用”或“空项目”，并选择 `x64` 平台。随后将以下文件加入项目：

```text
include/tacview/Tacview.h
include/tacview/AcmiEncoder.h
src/Tacview.cpp
src/AcmiEncoder.cpp
examples/TacviewExample.cpp
```

如果需要运行自动测试，请用下面的文件替换 `TacviewExample.cpp`：

```text
tests/TacviewTest.cpp
```

示例和测试都定义了 `main()`，不能同时加入同一个可执行项目，否则链接器会报告入口函数重复。

### 10.2 配置包含目录

打开“项目属性 → C/C++ → 常规 → 附加包含目录”，加入本模块的 `include` 目录，例如：

```text
D:\mycode\AircraftClass\AircraftClass\TacviewTCPlink\include
```

用户代码保持以下包含方式：

```cpp
#include "tacview/Tacview.h"
```

不要把路径写成 `include/tacview/Tacview.h`，因为 `include` 已经是编译器搜索目录。

### 10.3 配置编译选项

在“项目属性 → C/C++ → 语言 → C++ 语言标准”中选择：

```text
ISO C++14 标准 (/std:c++14)
```

也可以选择 C++17。随后在“C/C++ → 命令行 → 其他选项”中加入：

```text
/utf-8
```

### 10.4 配置 Windows Socket 库

在“项目属性 → 链接器 → 输入 → 附加依赖项”中加入：

```text
Ws2_32.lib
```

`Tacview.cpp` 已包含 MSVC 自动链接指令，但显式配置可以让项目依赖更清楚。

配置完成后即可直接生成并运行。该方法中 `Tacview.cpp` 和 `AcmiEncoder.cpp` 会与用户程序一起编译。

## 11. VS2019 集成方法二：链接预编译静态库

该方法适合向普通用户发布：用户只需要公共头文件和对应配置的 `.lib`，不需要把模块实现源码加入自己的项目。

### 11.1 所需发布文件

```text
include/
└── tacview/
    ├── Tacview.h
    └── AcmiEncoder.h

lib/
├── TacviewTCPlink_d.lib   Debug
└── TacviewTCPlink.lib     Release
```

用户项目只加入自己的 `main.cpp` 或业务源文件，不要再加入 `Tacview.cpp` 和 `AcmiEncoder.cpp`，否则会产生重复符号。

### 11.2 配置头文件目录

在“项目属性 → C/C++ → 常规 → 附加包含目录”中加入发布包的 `include` 目录：

```text
<TacviewTCPlink发布目录>\include
```

### 11.3 配置静态库目录

在“项目属性 → 链接器 → 常规 → 附加库目录”中加入：

```text
<TacviewTCPlink发布目录>\lib
```

### 11.4 配置链接库

在“项目属性 → 链接器 → 输入 → 附加依赖项”中分别设置：

Debug：

```text
TacviewTCPlink_d.lib
Ws2_32.lib
```

Release：

```text
TacviewTCPlink.lib
Ws2_32.lib
```

### 11.5 必须保持一致的构建配置

静态库与用户程序必须满足：

- 平台一致，例如都使用 `x64`；
- Debug 程序链接 `TacviewTCPlink_d.lib`；
- Release 程序链接 `TacviewTCPlink.lib`；
- Debug 使用 `/MDd` 运行库；
- Release 使用 `/MD` 运行库；
- C++ 标准至少为 C++14。

不要混用 Debug 和 Release 静态库。运行库或平台不一致通常会导致链接错误，也可能造成跨模块内存释放问题。

## 12. 推荐的 VS2019 解决方案结构

如果需要同时维护静态库、示例和测试，推荐创建三个项目：

```text
TacviewSolution
├── TacviewTCPlink   静态库项目
├── TacviewExample   控制台示例项目
└── TacviewTest      控制台测试项目
```

在解决方案中让两个可执行项目引用静态库项目：

```text
TacviewExample ─┐
                ├──> TacviewTCPlink
TacviewTest ────┘
```

这样 Visual Studio 会自动按照依赖顺序生成项目。对于第一次接入的用户，推荐使用第 10 节的“直接加入源码”；对于已经拿到正式发布包的用户，推荐使用第 11 节的“链接预编译静态库”。
